# Job Radar — Android app

A standalone Android app (min Android 14 / API 34) that pulls remote job listings — **any
industry, not just tech** — directly from public job-board APIs: **RemoteOK, Remotive, Arbeitnow,
Himalayas, We Work Remotely, Jobicy, Working Nomads**, plus optional **Adzuna** and **Jooble** if
you add a free API key in Profile. Filters them against your profile, and lets you apply with one
tap. Everything runs on-device — no backend server, no account, no dependency other than an
internet connection.

**Roles to apply for** (Profile tab) is a search-and-add box backed by a ~140-title database
spanning tech, HR, finance, business, marketing, sales, legal, education, healthcare, writing,
design, engineering, science, admin and hospitality — type to see matches, tap to add, or add your
own exact text as a custom filter if nothing matches. All the other Profile filters (years of
experience, minimum salary, work mode, region) are real hard filters now, not just cosmetic:
- **Years of experience** excludes postings whose title reads as clearly the wrong seniority tier
  (e.g. "Director"/"Principal" titles when you've set 1 year; "Junior"/"Intern" titles when you've
  set 10+).
- **Minimum salary** excludes any posting that states a salary below your floor. Postings with no
  stated salary are kept (most listings don't state one at all, so excluding them too would leave
  almost nothing).

A separate **Portals** tab covers the sites that don't allow automated search at all (Naukri,
LinkedIn, Indeed, foundit, Shine, TimesJobs, Glassdoor, Cutshort, Instahyre, Hirist, Wellfound,
iimjobs, Internshala, Freshersworld, Apna, WorkIndia, National Career Service) — each is a direct
link into that site's own search, pre-filled with your top role, so you tap through and apply
manually on their site. No scraping of these; their terms don't allow it, so this is the honest
alternative.

## What's in this folder

- `www/index.html` — the entire app (HTML/CSS/JS, one file, no external libraries).
- `android/` — a real Android Studio / Gradle project (generated by Capacitor), wrapping the app
  above in a native WebView shell with internet permission only.
- `capacitor.config.json` — app id `com.lakesh.jobradar`, native HTTP bridge enabled so the app can
  call the job APIs directly without browser CORS restrictions.

## How to build the APK

You need **Android Studio** installed (it bundles the Android SDK and build tools this project
needs — Gradle alone isn't enough). This machine doesn't have it installed, so do this on your end:

1. Install Android Studio: https://developer.android.com/studio (accept the SDK install prompts on
   first launch — it needs Android SDK Platform 34 and the matching build tools).
2. Open Android Studio → **Open** → select the `android` folder inside this project
   (`JobRadar\android`), **not** the `JobRadar` folder itself.
3. Let it finish Gradle sync (first time will download dependencies — needs internet).
4. Plug in your phone (USB debugging enabled) or start an emulator, then **Run ▶** to install and
   launch it directly, **or**
5. **Build → Build App Bundle(s) / APK(s) → Build APK(s)** to produce an installable `.apk` under
   `android/app/build/outputs/apk/debug/app-debug.apk`. Copy that file to your phone and install it
   (you'll need to allow "install from unknown sources" once, since it's not from the Play Store).

### Command-line alternative (once Android Studio/SDK is installed)

```bash
cd JobRadar/android
./gradlew assembleDebug
```

The APK lands at `android/app/build/outputs/apk/debug/app-debug.apk`.

## If you change the app

Edit `www/index.html`, then run this from the `JobRadar` folder before rebuilding in Android Studio:

```bash
npx cap sync android
```

## Profile filters (in the app)

- **Roles to apply for** — pick every title you'd accept (DevOps Engineer, SRE, Platform Engineer,
  Cloud Engineer/Architect, Infrastructure Engineer, SysAdmin, Release/Build Engineer, DevSecOps,
  Kubernetes Engineer, Automation Engineer, Cloud Solutions Architect). More roles selected = more
  matches.
- **Work mode** — Remote / Hybrid / On-site. Most free job boards only list remote roles, so
  Hybrid/On-site will show fewer or zero matches — that's a real limitation of the free sources,
  not a bug.
- **Years of experience**, **minimum salary (USD/year)**, **region preference** (foreign-first +
  India, foreign only, India only, no preference).
- **Scam filter** — on by default; screens out listings with common fake-job red flags (fees
  required to apply, "pay to start," wire-transfer requests, MLM language, missing company/URL,
  etc.). Can be turned off if you ever want to see everything unfiltered.
- **Company type** — Product-based only / Service-based only / Both. No job source tags this, so
  it's matched by company name against a list of ~60 known IT-services/consulting/BPO firms (TCS,
  Infosys, Wipro, Accenture, Cognizant, etc.). Anything not on that list is treated as
  product-based. Right for the large majority of listings, but a small or unfamiliar services firm
  not on the list will be miscounted as product-based — an honest heuristic, not a guarantee.
- **Resume** — stored only on your device (as a saved file in the app's local storage), never
  uploaded anywhere.

Filters apply immediately on the next "Refresh" — the app re-fetches and re-filters live every
time you tap it, so it always reflects your current profile settings.

## Honest expectation on volume

These are free, public APIs — actual daily inventory of genuinely matching remote DevOps-family
roles varies a lot day to day. After widening the pull (multi-tag Jobicy queries, deeper Himalayas
pagination, extra We Work Remotely categories), a live test found **32 real matches** in one run —
up from ~10 before, verified live, not padded. Widening your **Roles to apply for** checklist in
Profile is the single biggest lever for even more. There's no guaranteed fixed number; the app
shows everything real that currently matches your filters, nothing invented to hit a target.

## Company tab

Type any company's website (e.g. `stripe.com`). The app checks whether their careers page runs on
**Greenhouse** or **Lever** — two ATS platforms with genuinely public, documented job-board APIs —
and if so, searches it against your profile filters. Three outcomes:
- Matches found → shown as job cards, same as the main feed.
- Board found but nothing matches your profile → "No current jobs for your profile right now."
- Company isn't on Greenhouse or Lever (most aren't, including Amazon) → "I can't get inside this
  portal" — this isn't a bug, it's the honest answer, since there's no public API for their custom
  career sites without scraping (which this app deliberately never does).

## Verify company (on every job card)

No automated filter can guarantee a listing is legitimate — this button is help, not proof:
- **Registered-business check** — with a free API key from OpenCorporates (opencorporates.com,
  aggregates real government business registries worldwide) added in Profile, it searches for the
  company and shows real registry matches (jurisdiction, status). Without a key, it just says so —
  it never fakes a result.
- **Recruiter email domain check** — if the listing includes a contact email and the company's
  official domain is known (always true for Company-tab/Greenhouse/Lever results, since you typed
  the domain yourself), it compares them and flags a mismatch.
- **MCA (India)** and **GSTIN (GST portal)** quick-links — these government portals don't support
  pre-filled search links, so it opens the search page and you type the company name yourself,
  same as the Portals tab.
- **Visit official site** — opens the exact known company domain when available, or a web search
  for it otherwise.
- A closing reminder to do the one thing no app can automate: **contact the company yourself**,
  using a phone number or email found on their own official site — never one the recruiter gave
  you — before trusting any offer.
